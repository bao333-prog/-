# USB 摄像头接入与验收

## 使用
1. 在本地双击 start-local.cmd，打开 http://127.0.0.1:4173/；或使用已部署的 HTTPS 网页。不要通过普通局域网 HTTP 地址调用浏览器摄像头。
2. 插入烤箱 USB，选择“USB 摄像头”，点击“连接摄像头”，在浏览器提示中允许访问。
3. 首次授权前设备名称可能隐藏；授权后可刷新列表，再选择烤箱对应摄像头并重新连接。不要把电脑自带摄像头当作烤箱摄像头。
4. “识别当前画面”截取单帧进入已有模型流程。连续识别每次完成后再等 2 秒采集下一帧，避免队列堆积。
5. 手动选择食材时停止连续识别。切回上传、点击关闭、页面进入后台或离开时释放摄像头。

## 重连与权限
网站仅记住上次连接成功的设备 ID，不会在页面打开时直接启动摄像头。
勾选重连后，在本次主动连接的设备断开又重新插入时，尝试连接相同 ID；不会自动改用其他摄像头。设备变更事件的支持因浏览器而异，必要时使用“刷新设备”。ID 变化时需要重新选择。
连接等待超过20秒提示重试；授权结果在取消或超时后才返回时，会立刻关闭迟到的视频轨道。
拒绝权限后请到浏览器网站设置中允许；设备被占用时先关闭 Windows 相机、会议软件等。原文件上传入口始终保留。

## 数据路径
浏览器模型版：摄像头 → 本地 JPEG 单帧（最长边不超过1280）→ 当前浏览器模型。只申请视频，不申请麦克风；不会录制或自动下载录像。
Python 后端版：摄像头单帧发送到当前网站的 /api/predict；该接口按现有实现仅在内存处理。
识别结果对应截图时刻，不是实时画面内所有物体的检测结果，也不用于自动启动烤箱。

## 自动和浏览器检查
Node 测试覆盖：指定设备、关闭释放轨道、迟到授权、连接竞争、权限/占用错误、超时、USB ended、截图就绪与缩放；控制器测试覆盖连续任务串行、人工确认暂停、切换模式丢弃截图、断线清空和停止循环。
Python 接口测试同时检查新增摄像头脚本路由，避免后端页面出现404。
真实浏览器检查入口、设备列表、取消连接、切回上传，以及电脑 HD Camera 的预览和截图识别。烤箱摄像头未连接，不能宣称完成烤箱实机验收。

## 待接线验收（需要用户配合）
- 选择正确烤箱设备，确认显示炉腔而非电脑画面。
- 点击单帧识别，核对结果与采样图像；开启连续模式观察没有积压。
- 拔下 USB 后提示断开；重新插入后测试同设备重连，必要时刷新。
- 切回上传或关闭，确认摄像头占用/指示灯释放。
- 在实际演示浏览器和烤箱照明下测试，不将电脑摄像头结果当作烤箱准确率。
