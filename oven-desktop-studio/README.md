# OvenDesk 食材识别桌面版

Windows x64 桌面程序。使用旧发行版内的 ONNX 模型，在本地识别照片或摄像头拍摄的食材。这个仓库包含新的 WinForms 主程序、Python 推理与摄像头源码以及构建脚本。

## 构建

需要 Windows x64、系统的 .NET Framework 4.8 和原版 `OvenDesk-AI-Camera-Hotplug.exe`。构建脚本从原 EXE 读取模型和嵌入式依赖，并用仓库里的脚本生成新 EXE。构建过程无需联网。

```powershell
.\Build.ps1 -OriginalExe "C:\path\to\OvenDesk-AI-Camera-Hotplug.exe"
```

输出为 `build\OvenDesk-Optimized.exe`。运行新 EXE 无需另装 Python，也无需原版 EXE。上传源码时，`build/` 和逆向分析生成的 IL 已加入 Git 忽略列表。其他人要重新构建，需要一份同版本的原版 EXE。

## 使用

- **打开图片**或拖入 JPG、PNG、WebP，也可以打开摄像头预览后拍照识别。
- **测试识别**先用内置的合成图检查程序能否加载模型并完成一次推理。可以再选一张食材照片并填写正确标签，验证第一候选是否正确。
- **导出识别诊断**保存一个 ZIP。成功运行时包含实际送去归一化的 `input.png` 和 `result.json`。在识别失败时可导出错误，预处理成功时也会附上图片。结果 JSON 记录类别顺序、模型及预处理哈希、输入形状和候选分数。
- 出现**无法确认**时，可以选择候选、手动输入或重新拍照。当前规则为最高分低于 65%，或前两名分差不足 15 个百分点。这是待用实拍校准的初始规则。
- 相同进程内连续识别复用同一个 ONNX 会话。识别进程退出或超时时，下一次识别会重新启动它。
- 首次加载会在当前用户的 `%LOCALAPPDATA%\OvenDesk\Optimized` 内准备运行文件。每次启动推理进程前校验该版本的内嵌文件，缺失或损坏时从 EXE 恢复。
  可通过环境变量 `OVENDESK_CACHE_DIR` 指定另一个可写目录，例如在隔离测试中使用较短的路径。

## 命令行验证

```powershell
Start-Process -Wait -FilePath .\build\OvenDesk-Optimized.exe -ArgumentList '--self-test', 'self-test.json'
Get-Content .\self-test.json
```

也支持原有的 `--verify-image <图片>` 和 `--verify-classifier <图片> <输出文本>`。用 `Start-Process -Wait -PassThru` 获取退出码。包含空格的参数路径需要加双引号。

## 界面升级
点击“检查程序”会显示模型和摄像头取流的逐项结果。摄像头拍照后定格，再点击“识别这张”。“重新拍摄”恢复预览。照片亮度和细节提示采用启发式规则，仍需实拍验证。

“保存问题报告”可在识别前后使用，包含当前错误、自检和设备状态。识别后附上预处理图和结果。保存完成可打开所在文件夹。

“确认并保存训练素材”将当前识别照片与人工标签存入本地记录。相同文件内容按哈希去重，再次确认会更新标签。“识别记录 / 训练素材”支持查看原图、修改标签和导出已确认素材 ZIP，包含 images 和 labels.jsonl。

当前发布包没有原训练工程、训练权重和验证集。确认操作完成样本收集，继续训练当前模型需要补充原训练材料。现有功能不会自动产生或启用新模型。用户输入的新类别也会保存，训练端需要相应扩展类别。

验证完成了界面构造、模型推理、照片快照、记录保存和确认标签持久化。摄像头实际取流、图像质量提示准确率和真实食材识别效果仍需现场验证。

## 采集标签
确认前可填写层位（上、中、下、未知）、锡纸（有、无、未知）、拍摄批次与设备。摄像头拍摄自动带入设备名称和标识，导入照片时设备留空供手填。同一拍摄批次使用同一名称，换一批实物或拍摄场次时修改批次。层位和锡纸会保留上一次选择，确认前请检查。
历史记录选择照片后可修改全部标签。旧记录缺少的层位和锡纸显示未知。导出 labels.jsonl 包含 layer、foil、batch、device、imageSha256；group 使用人工填写的批次，未填时为空，需要训练前补全分组。模型和预处理不变，本次新增的是人工标注与导出。

## 模型升级与同图对照
“模型管理 / 切换版本”支持导入 ZIP、试运行、启用和切回内置或其他已导入版本。ZIP 根目录包含 food.onnx 和 food.json，后者使用仓库 food.json 的结构，可增加 version 字段。当前接口支持 RGB float32 NCHW 输入、[1, 类别数] logits 输出的单标签 ONNX 分类模型。类别数可变。PyTorch .pt 需要通过原训练工程导出 ONNX 后打包。模型包的类别映射应由导出工程生成，试运行只能检查结构和运行兼容性。
启用状态保存在用户模型目录，后续启动继续使用所选版本。失败的导入不会修改所选版本。

“同图对照”使用当前照片的固定副本，展示当前 EXE 和内置模型的版本、类别、候选和输入张量指纹，并允许调用本机网页版的 /api/predict。网页调用原始响应和 HTTP 状态会显示并进入报告，网页缺少的模型指纹与输入张量无法自动比较。需要先运行网页版服务器。

原始训练模型的结果可以导入 JSON。该文件需包含 sourceSha256（实际输入照片的 SHA256）、candidates（name/score 列表），可加 modelSha256、modelVersion、classes、tensorSha256。工具 tools/reference_result.py 可将原训练脚本已生成的候选列表包装成此格式，它不会执行 PyTorch 推理。ONNX 脚本支持 infer_desktop.py --json 图片 结果.json。原训练模型与部署模型的对比必须使用同一份原图。

保存对照报告会包含原图、本地两份预处理图和结果、网页或原始模型结果（如果已提供）与摘要。模型管理中的合成图检查不代表真实识别准确率。
