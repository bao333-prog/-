# 下一批数据怎样拍更有价值

当前两套开发对照保持A第二批83验证/84测试、B第一批193验证/第二批167测试。以下是后续数据版本的采集建议，不改变本轮划分或使用第一批牛排。

优先补香肠和芦笋：当前香肠易与鸡翅混淆，芦笋短段/茎段易与西兰花或薯条混淆。按你确认的食品状态拍不同实物、粗细、形态及摆放；香肠仍使用要识别的产品类型，芦笋的允许形态以你的确认范围为准。不要只给同一份食品增加几百张相邻帧。

先以每类10—20个不同实物作为补充训练的起步目标，按预算分阶段完成；这是采集建议，不是达到特定准确率的保证。固定实际摄像头，每个实物覆盖高/中/低层位、有/无锡纸、方向/摆放变化，尽量均衡。相机机位不移动，不人为改变烤箱灯光，也不需要采集额外熟化阶段。

整鸡目前没有实拍训练与评测，需要补真实烤箱数据才能判断第14类是否可用。牛排现205张来自一个采集session，应继续补新的实物/独立批次，沿用“只用第二批及后续合格实拍、不恢复第一批牛排”的要求。

每个实际食材建立稳定food_instance_id，同一根芦笋切成段、同一份食材换层位或换摆盘仍属于同一实物组。整组分到训练、验证或测试中的一个集合，不拆连拍凑比例。采集批次、类别、层位、锡纸、实物ID分别记录，不能把文件名前缀当作已确认的实物身份。本轮三个错误抽样分组就是来源记录缺失或沿用前缀导致。

未来新增验证与测试优先覆盖每类多个独立实物。可先以每类20—30张、来自多个新实物/批次作起步；原84/167张继续作固定开发对照，不会因重命名或换比例恢复盲测资格。B验证缺牛排，整鸡各评测缺数据，这些覆盖问题需要新数据补齐。

采集端保持曝光/白平衡设置一致。部分JSON有自动白平衡开启的记录，可请采集人员确认实际设置，减少相机自身引起的色彩漂移；这不需要改变灯光，也不重新启用颜色增强。保留原分辨率和原图，避免多次压缩。

16:9整图补边到224方形时，实际画面约224×126像素。小份、下层食材的细节会受限。若后续愿意增加食材位置框标注，可以再验证自动定位后放大；也可单独试较高输入尺寸，但需同时测部署延迟与内存。不能未经验证直接裁中间区域，避免丢掉下层食材。

建议记录字段：food_class、food_instance_id、capture_batch_id、split、rack_level、foil、shape、orientation、quantity、blur、occlusion、original_image_file。缺失字段保持缺失，不自动补成采集人员确认。

分组评测依据：[scikit-learn官方分组数据评测说明](https://scikit-learn.org/stable/modules/cross_validation.html#cross-validation-iterators-for-grouped-data)。独立组评测用于检查能否泛化到未见实物；上面的采集数量是结合本项目情况提出的起步建议。
